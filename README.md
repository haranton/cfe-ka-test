# CI расширения на Vanessa Runner

GitHub Actions загружает XML-исходники, обновляет расширение в существующей тестовой базе, проверяет применимость загруженного расширения и синтаксис его модулей штатными командами Vanessa Runner. Все параметры 1С находятся в файле autumn-properties.json.

## Конфиг

Укажите в autumn-properties.json:

- vrunner.ibconnection — существующую тестовую базу: /FC:\1C\Test либо /Sserver\database.
- vrunner.v8version — установленную версию платформы.
- vrunner.extension-name — имя расширения.
- vrunner.cfe.load.src — папку XML-исходников или готовый CFE.

Сейчас подключение настроено на файловую базу C:\Users\haran\OneDrive\Документы\vanessa, расширение MyExtension, платформу 8.3.27.1936. Для этой базы имя пользователя оставлено пустым. Если база требует авторизацию, пароль храните в Actions Secret ONEC_DB_PASSWORD, имя пользователя — в ONEC_DB_USER. Локально используйте переменные VRUNNER_DBPWD и VRUNNER_DBUSER.

При переносе проекта меняйте этот JSON. Если адрес базы должен оставаться только в настройках GitHub, задайте Actions Variable ONEC_TEST_CONNECTION: переменная VRUNNER_IBCONNECTION имеет приоритет над JSON.

## Команды

Запускайте из корня проекта после заполнения подключения:

```powershell
# Загрузить расширение и обновить его в тестовой базе.
vrunner cfe load

# Проверить возможность применения расширения с именем из конфига.
$config = Get-Content autumn-properties.json -Encoding UTF8 -Raw | ConvertFrom-Json
vrunner infobase extensions check $config.vrunner.'extension-name'

# Проверить синтаксис расширения для тонкого клиента и сервера.
vrunner validate syntax-check --target $config.vrunner.'extension-name' --mode ThinClient --mode Server
```

Vanessa Runner сам читает autumn-properties.json. Если загрузка, обновление, проверка применимости или синтаксиса завершаются ошибкой, проверка сборки в GitHub становится красной. Готовый CFE не выгружается, тесты не запускаются.

CI использует постоянную базу: данные сохраняются, расширение обновляется при каждом прогоне. Создание временных баз и загрузка основной конфигурации из CF не выполняются.

При загрузке XML платформа обновляет ConfigDumpInfo.xml в рабочем каталоге runner. Workflow не коммитит и не отправляет эти служебные изменения в Git.

## GitHub Actions

В .github/workflows/build-cfe.yml после vrunner cfe load запускаются проверка применимости и проверка синтаксиса в режимах ThinClient и Server. Обе проверки получают имя расширения из конфига и относятся к версии, загруженной этим прогоном. Остальные шаги получают коммит и проверяют заполнение подключения. Создание PR сейчас закомментировано. Отдельного build.ps1 нет.

Сборки всех веток выполняются последовательно. Вывод команды и ошибки видны в шагах Actions. Ошибка сборки делает проверку существующего PR красной.

## Одновременные пуши агента

Все ветки, использующие эту тестовую базу, должны включать актуальный workflow. Агент создает отдельную ветку на каждую задачу и отправляет полный каталог cfe. GitHub запускает отдельный CI для каждого push; checkout берет SHA события, а не последний коммит ветки на момент начала работы.

Группа concurrency имеет общее имя onec-test-base без имени ветки. Пока один запуск загружает и проверяет расширение, остальные ждут. cancel-in-progress: false не прерывает текущую сборку. queue: max сохраняет до 100 ожидающих запусков; при превышении этого лимита новые запуски отменяются GitHub. Порядок определяется попаданием в очередь, поэтому нельзя рассчитывать на порядок задач ITSM или время push.

Пример: агент одновременно отправил ветки task-A и task-B. Один прогон получает базу, полностью загружает свое расширение и выполняет проверки. После его завершения второй прогон загружает свой полный вариант расширения и выполняет свои проверки. Даже если первый завершился ошибкой, второй продолжает работу. Загружать только изменения через --increment для этого сценария не следует.

actions/checkout с clean: true очищает оставшиеся файлы и изменения рабочего каталога runner. Это относится к исходникам; данные постоянной базы сохраняются. Другая ветка не может подменить исходники текущего запуска.

В тестовой базе остается расширение последнего прогона, включая неуспешный: автоматического отката нет. Успешный результат CI относится к конкретному SHA и не означает, что этот SHA сейчас установлен в базе. После выбора версии ее можно повторно установить ручным запуском Actions для нужной ветки.

Эта очередь действует в пределах одного GitHub-репозитория. Другие workflow этого репозитория, работающие с той же базой, должны использовать ту же группу. Для другого репозитория выделите отдельную тестовую базу. Ручной запуск vrunner и открытый Конфигуратор не участвуют в очереди Actions; во время CI базу следует оставить runner.

Слияние в main выполняет владелец после ревью, успешного build_1c и одобрения. Ветка должна включать актуальный main. Новые коммиты снимают прежнее одобрение.

## Перенос

Подключите Windows runner к новому репозиторию, установите 1С, OneScript и Vanessa Runner, измените autumn-properties.json и Secrets. В GitHub разрешите Actions создавать PR и настройте защиту main с проверкой build_1c и одним одобрением.

ITSM-агент отправляет ветки в этот репозиторий. Если агент работает в другом GitHub workflow, используйте GitHub App token или PAT: push через встроенный GITHUB_TOKEN не запускает следующий workflow.

На текущем компьютере runner запускается после перезагрузки командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ci\start-runner.ps1

```
