# Сборка расширения 1С через GitHub Actions

После push ветки задачи GitHub Actions получает конкретный коммит, собирает проект в отдельной файловой базе 1С и сохраняет файлы поставки и логи. После успешной сборки создаётся pull request в `main`. Слияние выполняет владелец репозитория после ревью.

## Последовательность

1. Агент создаёт ветку от актуального `main`, изменяет XML-исходники и отправляет коммит в GitHub.
2. Задание `build_1c` создаёт новую базу для каждого запуска.
3. В базу загружается основная конфигурация, затем расширение; конфигурация БД обновляется.
4. Из собранной базы выгружаются `.cf` и `.cfe`.
5. GitHub сохраняет логи, файлы поставки и сведения о коммите.
6. Для успешной ветки открывается pull request. Повторные push обновляют ту же ветку и повторяют сборку.
7. Владелец проверяет изменения и результат сборки, одобряет PR и вручную объединяет его с `main` либо закрывает PR.

В первой версии выполняется сборка без модульных и сценарных тестов. Успешный статус подтверждает создание файлов поставки и обновление конфигурации БД.

## Окружение сборки

Сборочное задание выполняет выделенный self-hosted Windows runner с платформой 1С, лицензией, OneScript и Vanessa Runner. Для прототипа используются платформа `8.3.27.1936`, OneScript `2.2.0` и Vanessa Runner `3.0.2`.

Каждая сборка использует собственную базу. База разработки и общая пользовательская тестовая база не используются для сборки веток.

## Связь с агентом ITSM

Агент сохраняет номер задачи, имя ветки и SHA отправленного коммита. Статус сборки читается для этого SHA. Артефакты и ссылка на PR доступны в GitHub Actions.

Ветка задачи должна включать файл workflow из актуального `main`. Push должен создавать события GitHub Actions: встроенный `GITHUB_TOKEN` другого workflow не запускает workflow по событию push; для такого агента нужен GitHub App token, подходящий PAT либо явный dispatch.

## Ревью

Для `main` требуется успешное задание `build_1c` и одно одобрение. При новых коммитах предыдущее одобрение снимается. Автоматическое слияние не выполняется.

Workflow сборки запускается для push внутри этого репозитория. События pull request из внешних forks не запускают локальную сборочную машину.

## Артефакты

- Файл основной конфигурации `.cf`.
- Файл расширения `.cfe`.
- Логи отдельных операций 1С.
- Манифест со статусом, SHA коммита, версиями инструментов и контрольными суммами файлов поставки.

Файлы поставки публикуются после успешной сборки. Логи сохраняются также при ошибке. Создание PR выполняется отдельным заданием после сборки.
